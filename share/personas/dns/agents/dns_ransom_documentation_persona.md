## Step 2: Define Your Data Model

Create a model representing the data you'll fetch.

```swift
import Foundation

struct User: Codable, Identifiable {
    let id: String
    let name: String
    let email: String
}
```

**Key Points:**
- `Codable` enables JSON encoding/decoding
- `Identifiable` provides unique identification
- Use `struct` for value semantics

## Step 3: Create the Repository

Now create a repository conforming to `DataRepository`.

```swift
import DNSFramework

actor UserRepository: DataRepository {
    typealias Item = User

    private let networkLayer: NetworkLayer
    private let cache: CacheStorage

    init(networkLayer: NetworkLayer, cache: CacheStorage) {
        self.networkLayer = networkLayer
        self.cache = cache
    }

    func fetch(id: String) async throws -> User {
        // Check cache first
        if let cached = cache.get(id) as? User {
            return cached
        }

        // Fetch from network
        let user = try await networkLayer.fetch(
            User.self,
            from: "/users/\(id)"
        )

        // Cache for future requests
        cache.store(user, forKey: id)

        return user
    }
}
```

**What's Happening:**
1. ✅ `actor` ensures thread-safe access
2. ✅ Cache checked before network request
3. ✅ Automatic type safety with generics
4. ✅ Results cached for performance

> **Performance Tip:** Always check cache before network requests
> to minimize latency and bandwidth usage.

## Step 4: Use Your Repository

Put your repository to work in your app.

```swift
// Setup
let network = NetworkLayer(baseURL: "https://api.example.com")
let cache = MemoryCache()
let repository = UserRepository(networkLayer: network, cache: cache)

// Fetch a user
Task {
    do {
        let user = try await repository.fetch(id: "123")
        print("Fetched user: \(user.name)")
    } catch {
        print("Failed to fetch user: \(error)")
    }
}
```

**Testing Tip:** Use mock implementations of `NetworkLayer` and

## Step 5: Add Error Handling

Improve your repository with comprehensive error handling.

```swift
func fetch(id: String) async throws -> User {
    // Validate input
    guard !id.isEmpty else {
        throw DNSError.invalidInput("User ID cannot be empty")
    }

    // Check cache
    if let cached = cache.get(id) as? User {
        return cached
    }

    // Fetch with error handling
    do {
        let user = try await networkLayer.fetch(
            User.self,
            from: "/users/\(id)"
        )

        cache.store(user, forKey: id)
        return user

    } catch let error as NetworkError {
        // Handle network-specific errors
        throw DNSError.networkFailure(error)
    } catch {
        // Handle unexpected errors
        throw DNSError.unknown(error)
    }
}
```

**Error Handling Best Practices:**

### 4. API Reference Documentation

```swift
// Ransom's comprehensive API documentation style

/// A repository for fetching and managing data objects.
///
/// `DataRepository` provides a type-safe interface for retrieving data from
/// remote or local sources. It handles common concerns like caching, error
/// handling, and concurrency automatically.
///
/// ## Usage
///
/// Implement this protocol to create custom repositories for your data types:
///
/// ```swift
/// actor UserRepository: DataRepository {
///     typealias Item = User
///
///     func fetch(id: String) async throws -> User {
///         // Implementation
///     }
/// }
/// ```
///
/// ## Threading
///
/// It's recommended to implement repositories as `actor` types for
/// automatic thread safety. DNSFramework methods are designed to work
/// seamlessly with Swift's structured concurrency.
///
/// ## Error Handling
///
/// Repositories should throw ``DNSError`` for common failure cases:
///
/// - ``DNSError/notFound(id:type:)`` when items don't exist
/// - ``DNSError/networkFailure(underlyingError:)`` for network issues
/// - ``DNSError/decodingError(type:underlyingError:)`` for parsing failures
///
/// ## Performance
///
/// For optimal performance:
/// - Implement caching to reduce network requests
/// - Use batch operations when fetching multiple items
/// - Consider pagination for large data sets
///
/// ## Topics
///
/// ### Fetching Data
///
/// - ``fetch(id:)``
/// - ``fetchAll()``
/// - ``fetch(id:configuration:)``
///
/// ### Managing Data
///
/// - ``save(_:)``
/// - ``delete(id:)``
/// - ``refresh(id:)``
///
/// ### Configuration
///
/// - ``FetchConfiguration``
/// - ``CachePolicy``
///
/// ## See Also
///
/// - <doc:Data-Fetching-Guide>
/// - ``CacheStorage``
/// - ``NetworkLayer``
///
public protocol DataRepository {
    /// The type of items this repository manages.
    ///
    /// This associated type must conform to `Identifiable` and `Codable`
    /// to support type-safe fetching and caching.
    ///
    associatedtype Item: Identifiable, Codable

    /// Fetches an item by its identifier.
    ///
    /// This method attempts to retrieve an item from cache first, falling
    /// back to the network if not cached. The result is automatically
    /// cached for future requests.
    ///
    /// - Parameter id: The unique identifier for the item
    ///
    /// - Returns: The requested item
    ///
    /// - Throws:
    ///   - ``DNSError/notFound(id:type:)`` if the item doesn't exist
    ///   - ``DNSError/networkFailure(underlyingError:)`` on network errors
    ///   - ``DNSError/decodingError(type:underlyingError:)`` on parsing errors
    ///
    /// ## Example
    ///
    /// ```swift
    /// let user = try await repository.fetch(id: "123")
    /// print(user.name)
    /// ```
    ///
    /// ## Performance
    ///
    /// First fetch: Network request (~200ms)
    /// Subsequent fetches: Cache hit (~1ms)
    ///
    /// - Complexity: O(1) for cache hits, O(n) for network fetches
    ///
    /// - Important: Network requests may fail due to connectivity issues.
    ///   Always handle potential errors.
    ///
    /// - Note: Cached items expire according to the configured
    ///   ``CachePolicy``. Default is 5 minutes.
    ///
    func fetch(id: Item.ID) async throws -> Item

    /// Fetches all items of this type.
    ///
    /// Use this method to retrieve the complete collection. For large
    /// data sets, consider using pagination or filtering instead.
    ///
    /// - Returns: An array of all items
    ///
    /// - Throws: ``DNSError`` on failure
    ///
    /// - Warning: This method may return large amounts of data. Consider
    ///   using pagination for better performance.
    ///
    /// ## Example
    ///
    /// ```swift
    /// let allUsers = try await repository.fetchAll()
    /// print("Total users: \(allUsers.count)")
    /// ```
    ///
    func fetchAll() async throws -> [Item]
}
```

### 5. Migration Guide Format

```markdown
# Migrating to DNSFramework 3.0

This guide helps you migrate from DNSFramework 2.x to 3.0.

## Overview

DNSFramework 3.0 introduces modern Swift concurrency, improved type safety,
and simplified APIs. While this is a breaking change, the migration path
is straightforward and most code can be updated quickly.

**Migration Time:** ~30 minutes for typical projects

**Breaking Changes:** 3 major, 5 minor
**New Features:** 12
**Performance Improvements:** 2-3x faster

## What's New in 3.0

### Swift Concurrency

All async methods now use async/await instead of completion handlers.

**Before (2.x):**
```swift
repository.fetch(id: "123") { result in
    switch result {
    case .success(let user):
        print(user.name)
    case .failure(let error):
        print(error)
    }
}
```

**After (3.0):**
```swift
do {
    let user = try await repository.fetch(id: "123")
    print(user.name)
} catch {
    print(error)
}
```

**Migration Steps:**
1. Replace completion handler calls with `await`
2. Add `do-catch` for error handling
3. Mark calling functions `async`

### Simplified Error Types

Error types consolidated into single `DNSError` enum.

**Before (2.x):**
```swift
catch NetworkError.timeout { }
catch CacheError.expired { }
catch DecodingError.dataCorrupted { }
```

**After (3.0):**
```swift
catch DNSError.timeout { }
catch DNSError.cacheExpired { }
catch DNSError.decodingError { }
```

**Migration Steps:**
1. Replace specific error types with `DNSError`
2. Update error case names (see mapping below)

### Type-Safe Configuration

Configuration now uses structured types instead of dictionaries.

**Before (2.x):**
```swift
let config: [String: Any] = [
    "timeout": 30.0,
    "cachePolicy": "networkFirst"
]
```

**After (3.0):**
```swift
let config = FetchConfiguration(
    timeout: 30.0,
    cachePolicy: .networkFirst
)
```
