# CR style (Academy default)

Write for a reader who is not an engineer. Say what changes for the people who use the
product, in plain sentences, in the present or future tense.

- Keep every field short. The whole CR should read in a couple of minutes.
- No ticket IDs, pull request numbers, commit hashes, file names or code terms.
- Lead the Description with the outcomes a user would notice. Internal-only work is
  covered by the single "behind-the-scenes maintenance" line the template adds.
- Reason for change: one to three sentences, user impact first.
- Testing: say what was checked in plain words. Do not claim testing that did not happen.
  Include the Testing Log link exactly once.
- Rollback: state plainly how the change is undone if a problem appears.
